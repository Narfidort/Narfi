# v3 設計の下書き 1：宣言（def・notation・axiom・thm …）の見直し

v3 では言語の表側（構文・宣言・推論の道具・標準ライブラリ）を作り直す。kernel・証明の文・自然言語の読み・Web とクラウドは引き継ぐ。
この文書は、その最初として **宣言** を「導入する側」と「使う側」の両面から見直す。ベンチマーク（[../bench.md](../bench.md)）で実際に困った所を根拠にする。

## 1. 今の宣言と、困ったこと

| 宣言 | 導入する側で困ること | 使う側で困ること |
|---|---|---|
| `def`（述語） | 型が固定で、型の変数を持てない。見た目（記法）と推論の規則を一緒に書けない | 自動で開く（よい）。開いた形で `choose`・`cases` が使える |
| `def`（値） | 同上。集合・関数を返す定義が書けても使えない | `∈` や適用の中で開かない（`x ∈ cup(A, B)` を `x ∈ A ∨ x ∈ B` にできない：K1） |
| `rec` | `def` と別の宣言。生成される定理（`sum.zero`・`sum.succ`）は「推論の規則」の先例 | 規則を毎回名前で引く |
| `notation` | `def` と別の宣言で、名前を 2 回書く。組み込みの記号（`∪`・`∣`・`∘`）に意味を付けられない。意味も推論も持たない | 「読めるのに使えない」記号ができる（`∪`）。打ち方の補完が型紙から作られない |
| `axiom` | 定義のない定数（測度 $\mu$・微分 `deriv`）を宣言できない。`axiom c : ℝ` が黙って変な公理になる（バグ）。根本の公理と、ライブラリの仮置きの補題が同じ `axiom` | 書き方が 2 通りで使い方も違う：`∀` で書いた `triangle(a, b)` と、仮定で書いた `pos_half(h)` |
| `thm` | 共通の前提（ベクトル空間の公理など）を毎回並べる（中線定理の仮定が 7 行） | 推論の規則（導入・除去・書き換え）として登録できない。変数を明示して渡す書き方がない |
| `typedef` | 部分型・商を作る（ℝ = コーシー列 / ~）。構造（ベクトル空間）とは別物 | `T.abs`・`T.rep` を手で使う |
| ない | 型と演算と公理と記法をまとめる **構造**、共通の前提をまとめる **文脈**、**場合分け** の定義 | |

根っこは 1 つ：**数学で概念を導入するときに一緒に決めること（名前・意味・見た目・使い方）を、ばらばらの宣言でしか書けず、「使い方」はどこにも書けない。**

## 2. 方針
1. **1 つの概念は 1 か所で導入する。** 意味（核の定義）と見た目（記法）を同じ宣言に書き、使い方（性質）はその直後に定理として書く。
2. **組み込みの記法も同じ仕組みで作る。** `|x|`・`∪`・`max{a, b}`・Σ などは prelude・標準ライブラリで宣言する。構文解析に個別に作り込まない。残す組み込みは、論理（∀ ∃ ⇒ ∧ ∨ ¬）・関数の適用と添字 `a_n`・λ・集合の内包表記・等号と順序くらい。
3. **使い方は定理として書く。** 定義は、`choose`・`cases` などが必要とするときに検査器が開く（値の定義も、`∈` や適用の中でも）。それ以外の性質は普通の `thm` で、根拠に名前を書いて使う（原則 2）。使い方のための特別な宣言（「規則」）は作らない。
4. **kernel は変えない。** 構造は「定数と公理を引数に持つ定理」に落とす（原則 1）。

## 3. 提案

### 3.1 def：意味と見た目をまとめる
```
def union(A : Set α, B : Set α) : Set α := {x | x ∈ A ∨ x ∈ B}
  notation A ∪ B

thm union.comm :
  A : Set α, B : Set α
  ⊢ A ∪ B = B ∪ A
…
```
- 1 行目：**意味**。`α` は型の変数（どんな型でもよい）。`Set α` は `α → Prop`。
- `notation`：**見た目**（1 つの概念に 1 つ）。型紙の名前は引数の名前。
- **使い方**は普通の定理。名前を `.` の階層（`union.comm`）にして、定義の直後に置く。
- `x ∈ A ∪ B` は、検査器が定義を開いて β 簡約すれば `x ∈ A ∨ x ∈ B` になる（K1 の修正）。だから `left`・`cases` はそのまま使え、「要素の規則」を別に書く必要はない。定義を開いただけの一歩は、根拠に `union.def` と書く（今の `名前.def` と同じ）。
- 検討の経緯：はじめは使い方を `rule` という別の宣言にする案だったが、「定義を開けること」と「普通の定理」で足りるので、やめた。

束縛を含む記法も、引数の名前で書ける：
```
def converges(a : ℕ → ℝ, α : ℝ) :⇔ ∀ε>0. ∃N. ∀n≥N. |a_n − α| < ε
  notation a_n → α (n → ∞)
```
型紙の中の、引数でない名前（`n`）は束縛変数。引数 `a` が束縛変数に添字で付いた `a_n` は「n を含む式が入る所」で、`a` はその式の関数（v2.9 では右辺に λ を書いていた所を、引数の名前で書ける）。

値の定義も同じ：
```
def abs(x : ℝ) : ℝ := max{x, −x}
  notation |x|

thm abs.nonneg :
  x : ℝ
  ⊢ |x| ≥ 0
…
```
開くと使いにくい定義（選択 `some` で定義した `sup A` など）は、開かずに性質の定理（`sup.spec`）を名前で引く。

### 3.2 const：定義のない記号
```
const μ : Set ℝ → ℝ
```
- 意味は公理か、構造（3.4）で与える。`axiom c : ℝ` のような書き方はエラーにする。
- 普段は構造の中で使い、単独の `const` はめったに書かない。

### 3.3 axiom と thm：書き方と使い方を 1 つに
- 書き方は `thm 名前 : 前提の並び ⊢ 結論` の 1 通り（`axiom` も同じ）。結論に `∀` を書いてもよいが、使い方は変わらない。
- 使い方は `名前(証明, …)`。前提の並びの変数は単一化で決まる。決まらないときだけ、名前を付けて渡す：`名前[x := t](…)`。
  （今の `triangle(a, b)` と `pos_half(h)` の違いがなくなる）
- `axiom` は、根本の公理（prelude）と構造の公理だけに使う。ライブラリでまだ証明していない補題は `thm … sorry` にし、使った定理は「未完成に頼る」と表示する（信頼の区別をはっきりさせる）。

### 3.4 structure：型と演算と公理と記法をまとめる
```
structure VectorSpace(V)
  zero : V                     notation 0
  add : V × V → V              notation u + v
  smul : ℝ × V → V             notation c v
  add.comm : ∀u v. u + v = v + u
  …
```
- 使う側：`V : VectorSpace` と書けば、`u + v`・`0`・公理がその場で使える。
- 同じ記号 `+` が、ℝ の和にも V の和にもなる。**どちらの意味かは型で 1 つに決まる**（notation.md の決まり。両方当てはまればエラー）。
- kernel には「V の演算と公理を引数・前提に持つ定理」として渡る。kernel は変えない。
- 継承（内積空間はベクトル空間）、具体例（ℝⁿ はベクトル空間）の宣言も要る。

### 3.5 context：共通の前提をまとめる
紙の「以下、V はベクトル空間、T は線形写像とする」に当たる。
```
context
  V : VectorSpace, T : V → V, hT : linear(T)

thm ker.add :
  u : V, v : V, hu : T(u) = 0, hv : T(v) = 0
  ⊢ T(u + v) = 0
…
end
```
文脈の中の定理には、文脈の前提が付く（外から使うときは、前提の分も渡す）。

### 3.6 rec と場合分け
- `rec` は `def … by recursion on n` の形にして、2 つの等式を定理（`sum.zero`・`sum.succ`）として作る（今と同じ）。
- 場合分けの定義：`def f(x : ℝ) : ℝ := if x ≥ 0 then x else −x`。条件ごとの値の定理（`f.pos`・`f.neg`）を自動で作る。

## 4. 使う側：定義と定理をどう使うか
| 使い方 | 何を使うか | 書くもの |
|---|---|---|
| `choose`・`cases`・`Obtain` | 定義を必要なだけ開いた形（∨・∃・∧） | 今までどおり（Goal の表示は開く前の形のまま） |
| 定義を開いただけの一歩 | 定義 | 根拠に `名前.def`（Prose には「定義より」） |
| 性質・書き換え | 定理 | 根拠に定理の名前（`by union.comm`） |
| 同値の連鎖 | 定義・定理 | `⇔ … by 根拠` を連ねる（新しい書き方。下の例） |

代入（R1）・∀ の具体化（R2）・関数の等式（R3）・帰納法の後者（R4）は、宣言ではなく推論の道具の話なので、次の文書（推論の道具）で扱う。

## 5. 例：ベンチマークの書き直し
集合（今は ✗）：
```
import set

thm preimage.union :
  f : α → β, A : Set β, B : Set β
  ⊢ f^{-1}[A ∪ B] = f^{-1}[A] ∪ f^{-1}[B]

ext x
  x ∈ f^{-1}[A ∪ B]
    ⇔ f(x) ∈ A ∪ B                     by preimage.def
    ⇔ f(x) ∈ A ∨ f(x) ∈ B              by union.def
    ⇔ x ∈ f^{-1}[A] ∨ x ∈ f^{-1}[B]    by preimage.def
    ⇔ x ∈ f^{-1}[A] ∪ f^{-1}[B]        by union.def
```
紙の証明（「$x \in f^{-1}[A \cup B] \iff f(x) \in A \cup B \iff \dots$」）と 1 行ずつ対応する。`ext x` は「集合の等号を要素で示す」文（外延性）。

中線定理（今は仮定 7 行）：
```
import linear.inner_product

thm parallelogram :
  V : InnerProductSpace, x : V, y : V
  ⊢ ‖x + y‖² + ‖x − y‖² = 2‖x‖² + 2‖y‖²

‖x + y‖² + ‖x − y‖²
  = ⟨x + y, x + y⟩ + ⟨x − y, x − y⟩                           by norm.sq
  = (‖x‖² + 2⟨x, y⟩ + ‖y‖²) + (‖x‖² − 2⟨x, y⟩ + ‖y‖²)        by inner.add, inner.sub
  = 2‖x‖² + 2‖y‖²                                              by ring
```

測度の単調性（今は ✗）：`μ : Measure` と書けば、加法性・非負性は構造の公理として使える。

## 6. 決めること
1. 型の変数の書き方：`α`・`β`（ギリシャ文字の小文字は型の変数）か、`'a`（今の kernel の内部の書き方）か。
2. 定義を自動で開く範囲：`choose`・`cases` などが必要とするときだけ（今の述語と同じ）でよいか。（使い方の別の宣言 `rule` は作らないことにした）
3. 独立した `notation`（他人の定義に後から記法を付ける。研究の記法 R・個人の記法 P 用）を残すか。
4. ライブラリの仮置きを `thm … sorry` にするか、`axiom` に別の印を付けるか。
5. 構造の継承と具体例の宣言の形。
6. 変数を名前で渡す書き方（`名前[x := t]` の案）。
