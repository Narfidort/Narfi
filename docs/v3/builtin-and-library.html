v3 設計の下書き 0：組み込み・標準ライブラリ・宣言の種類

宣言の見直し（declarations.md）の土台。どこまでを言語に組み込み、どこからを標準ライブラリにするかを、層の考え方で決め直す。

1. 層（理論の整理）

層中身
-1意味（イデア界）。Narfi は持たない。記法・Prose は読む人がここへ届くための道具
0記号と文法：記号・型・項・文脈・λ・適用・代入という操作
1構造：同一律（A ⊢ A）・カット（導出をつなぐ）・代入で導出が保たれる
2論理の作用素：=・∀・∃・∧・⇒・∨・⊥。それぞれ導入と除去の規則（代入に対する普遍性）で決まる。反射律・代入原理は = の導入・除去
2′体系の選択：古典論理にするか（排中律）、選択公理を入れるか。組み込みにしない。core の公理として選ぶ（選択と外延性から排中律が出る：ディアコネスクの定理）
3数学の公理：高階論理（HOL）。外延性・選択・無限（ℕ）
4定義：記号を足し、その意味を定義で与える（何も新しく主張しない＝保存拡大）
5定理：証明して足す

2. 線引きの基準

組み込み（言語そのもの）にするのは、宣言では作れないものだけ。 つまり 0〜2 層（直観主義の論理まで）と、宣言の仕組みそのもの。体系の選択（2′）は core の公理で選ぶ。 それ以外は宣言で書き、ファイルとして読める形で置く。

区分中身置き場所公理を書けるか
言語0〜2 層：文法・型・λ・代入、論理の作用素とその規則（直観主義）、証明の文、宣言の種類kernel と構文解析（Rust）—
core2′・3 層の公理（古典論理・選択・外延性・ℕ）と、すべての土台になる定義：論理・集合・関数の基本lib/core/ここだけ（と構造の中）
標準ライブラリ4・5 層：数の体系（ℤ・ℚ・ℝ）、集合・写像、代数・解析・線形代数…lib/書かない（未証明は thm … sorry）
ベンチマーク・例受け入れ試験lib/bench/・examples/書かない

3. 言語に組み込むもの（これだけ）

文法（0 層）

  • 記号・名前（. の階層）・数字の並び・括弧・カンマ
  • 型：基本の型の名前、関数の型 σ → τ、積 σ × τ、Prop、型の変数 α
  • 項：変数・適用 f(x)・λ (x ↦ t)・内包表記 {x | φ}
  • 添字・上付き・分数などの 見た目の構造（意味は持たない。a_n を a(n) と読むのは core の記法）
  • 型紙の記法を読む仕組み（宣言された記法で読む。型で 1 つに決まるときだけ型で選ぶ）

論理（1〜2 層）

  • =（反射律・代入原理）、∀・∃、∧・⇒・∨・⊥ と、その導入・除去の規則（直観主義の自然演繹）
  • kernel はこれだけを知る。背理法の規則は持たない

体系の選択（2′ 層）は core で

  • core/classical：排中律（公理、または選択からの定理）。by_contra はこれを使う。読まなければ直観主義（LJ）
  • core/choice：選択公理（入れると古典論理も付いてくる）
  • 定理ごとの「依存する公理」に「古典論理」「選択」が出るので、構成的に証明できているかが見える

証明の文

  • Fix・assume・Obtain・cases・choose・事実の行・連鎖・∴
  • by_contra：core/classical の排中律を使う文（読んでいなければ使えない）
  • induction：ℕ の帰納法の公理（core）を使う文。将来は帰納的な型に一般化

5. 宣言の種類（宣言語）

宣言層何をするか書ける場所
type T0新しい基本の型を足す（中身は決めない）主に構造の中
const c : σ0記号を足す（意味は決めない）主に構造の中
axiom 名前 : 前提 ⊢ 結論3主張を足す（証明なし）core と構造の中だけ。ほかで書くとエラー
def 名前(引数) : σ := 項、def 名前(引数) :⇔ 命題4記号＋定義。型の変数を持てる。下に notationどこでも
def … by recursion on n4原始再帰（等式 2 つの定理を作る）どこでも
type T := {x : σ | φ}、type T := σ / ~4部分型・商（今の typedef）どこでも
notation 型紙0 の見た目記号の見た目（def・const・構造の欄の下に書く）宣言の下
thm 名前 : 前提 ⊢ 結論5証明して足すどこでも
structure S(T)0〜3 をまとめる型の変数・演算（const）・公理（axiom）・記法・extendsどこでも（公理はこの中なら書ける）
instance … : S4・5具体的な型が構造を満たすこと（演算の定義と公理の証明）どこでも
context … end—共通の前提をまとめる（「以下 V はベクトル空間とする」）どこでも
import・@name・edition—ファイルの読み込み・訳名・版ファイルの最初

使う側の決まり

  • 定理・公理の使い方は 1 通り：名前(証明, …)。前提の並びの変数は単一化で決まる。決まらないときだけ 名前[x := t](…)。
  • 定義は、choose・cases などが必要とするときに検査器が開く（値の定義も、∈ や適用の中でも）。開いただけの一歩の根拠は 名前.def。
  • 構造の演算・記法は、型で 1 つに決まる（+ が ℝ の和か、V の和か）。決まらなければエラー。
  • 定理ごとに「どの層のどの公理に頼っているか」を表示する。core の公理・構造の公理・sorry を区別する。

6. 例：core の一部

-- core/logic
def not(P : Prop) :⇔ P ⇒ ⊥
  notation ¬P

def iff(P : Prop, Q : Prop) :⇔ (P ⇒ Q) ∧ (Q ⇒ P)
  notation P ⇔ Q

-- core/set
def Set(α) := α → Prop
def mem(x : α, A : Set α) :⇔ A(x)
  notation x ∈ A
def union(A : Set α, B : Set α) : Set α := {x | x ∈ A ∨ x ∈ B}
  notation A ∪ B

-- algebra/ordered_field
structure OrderedField(F)
  zero : F            notation 0
  one : F             notation 1
  add : F × F → F     notation a + b
  mul : F × F → F     notation a b
  le : F × F → Prop   notation a ≤ b
  add.comm : ∀a b. a + b = b + a
  …
def abs(x : F) : F := max{x, −x}      -- F : OrderedField の文脈で
  notation |x|

7. 決めること

  1. 型の変数の書き方：α・β（ギリシャ文字の小文字）か 'a か。
  2. 独立した notation（他人の定義に後から記法を付ける）を残すか。
  3. axiom を core と構造の外で書いたら、エラーにするか、強い警告にするか。
  4. 数字の扱い：ℕ 以外の型の 2 を、構造（「1 と足し算を持つ」）から作るか。
  5. ℝ を構成するまでの「仮の組み込み」の範囲（ℝ の型・四則・順序・ring・linarith）。
  6. induction を ℕ 専用のまま始めるか、帰納的な型（リスト・木）・帰納的に定義する述語を最初から入れるか。（線形論理などを「対象として」扱う＝深い埋め込みには、帰納的な定義が要る）
  7. 論理の枠組みにするか（将来）：論理そのもの（規則・構造規則の有無）を宣言で載せられるようにし、線形論理などで証明を書けるようにする。Isabelle・LF の考え方。教科書の数学を紙のとおりに書く目的からは遠くなるので、必要が見えてから決める。

8. v2.13 で先に入れたもの

v3 を待たずに、今の Narfi に入れたもの（v3 でも引き継ぐ）：

  • const c : σ。axiom c : ℝ のような書き方は、const を案内するエラーにした。
  • 記法を定義の下に書く形（def … の下に字下げして notation 型紙）。独立した notation も残す。
  • 意味のない組み込みの ∪・∩・∖ を外し、lib/set/real.narfi で定義と記法を与えた（実数の集合だけ）。
  • 集合を返す定義に要素を当てた形を、kernel が開ける（δ と β）。
  • 根拠に等式を書けば代入として使う。関数どうしの等式を ring で示せる。書き換えのあとに β 簡約する。
  • 消した書き方：have・suffices・contradiction・unfold（今の書き方を案内するエラー）。

まだのもの（v3）：型の変数を持つ定義、構造・instance・context、import と記法の有効化を分けること、kernel を直観主義にして古典論理を core に移すこと、ℕ の k + 1 を後者として読むこと。
