# 2. 型（ソート）：なぜ必要で、どう決めるか

## 2.1 v1 で型がないと何が困ったか

v1 は `∀n:ℕ` と書いても、`n` に実数や負の数を代入するのを止めなかった。たとえば

```narfi
thm u.nat.sub :
  n : ℕ
  ⊢ n - 1 < n
```

は、整数として計算すれば正しい（n − 1 < n）。しかし ℕ で考えると、`0 - 1` は定義されていない
（ペアノの公理に引き算はない）。引き算を「0 未満なら 0」と決めれば `0 - 1 = 0` で、`0 < 0` は偽。

つまり **同じ文字列でも、どの数の世界で読むかで真偽が変わる**。どの世界で読むかを決めずに
「正しい」と言うことはできない。これが型を検査する理由。v2 ではこの文は
「引き算：ℕ では使えない演算がある（ℤ 以上が必要）」として止まる（`tests/unsound_sorts.narfi`）。

## 2.2 多ソート一階述語論理

v2.0 の論理は **多ソート一階述語論理**。普通の一階述語論理では「対象」は1種類だが、
多ソートでは対象に種類（ソート）がある。

- ソート：`ℕ`・`ℤ`・`ℚ`・`ℝ`
- 関数記号には型がある：`+ : ℝ × ℝ → ℝ`、`S : ℕ → ℕ`、利用者の `a : ℕ → ℝ`（数列）
- 述語記号にも型がある：`P : ℕ`、`< : ℝ × ℝ`
- 量化子は型ごと：`∀x:ℝ. φ` は「すべての実数 x について φ」

「型がついている」ことは、次の規則で確かめる（仕様 §3.1、`src/kernel/env.rs` の `check_t`・`check_f`）。

```
x : σ が文脈にあれば、x の型は σ
f : σ₁ × … × σₙ → σ で、各 tᵢ の型が σᵢ なら、f(t₁, …, tₙ) の型は σ
```

型理論の言葉では、これは **型付け判断** `Γ ⊢ t : σ` を導く規則。

## 2.3 型の推論 = 単一化

毎回すべての変数に型を書くのは面倒なので、elab が推論する（`src/sorts.rs`）。やり方は：

1. 変数・数字・演算の結果ごとに「型の箱」を作る。
2. 「同じ型であるべき」箱をつなぐ。`a + b` なら `a` と `b` と結果の3つ。`a < b` なら `a` と `b`。
3. つながった箱のグループに、書かれた型（`x : ℝ`）があればそれで決まる。

箱をつなぐのに **union-find**（素集合データ構造）を使う。これは Hindley–Milner 型推論
（ML・Haskell の型推論）の一番簡単な場合と同じ考え方。

さらに、箱には「数でなければならない」「ℤ 以上でなければならない（引き算を使った）」
「ℚ 以上（割り算を使った）」という条件をつける。

### 決まらないとき

```narfi
axiom pos_half : h : x > 0 ⊢ x/2 > 0
```

`x` は割り算に使われているので ℚ か ℝ のどちらか。v2 はここで推測せず、
「`x` の型が決まらない（ℚ・ℝ のどれか）。`x : ℝ` のように型を書く」と止まる。
ℚ と ℝ では成り立つ定理が違う（たとえば √2 が存在するか）ので、勝手に決めてはいけない。

## 2.4 数字の型

`1/2 + 1/2 = 1` のように **数字だけ** の式は、周りから型が決まらない。
これは困らない。ℕ ⊂ ℤ ⊂ ℚ ⊂ ℝ の埋め込みは `+ · - / < =` を保つので、どの世界で計算しても
真偽が同じだから。そこで「使った演算が意味を持つ最小の世界」で読む（仕様 §3.2）。

数学的に言うと、埋め込み写像 ι : ℕ → ℤ が準同型で順序を保つ（ι(a+b) = ι(a)+ι(b)、a < b ⇔ ι(a) < ι(b)）
ことを使っている。

## 2.5 ソート変数（多相性）

```narfi
thm eq.symm :
  h : x = y
  ⊢ y = x
```

`x`・`y` には何の制約もない。これは「どんな型でも成り立つ」定理なので、型を1つに決めずに
**ソート変数** `'a` を置く（`x : 'a`, `y : 'a`）。使うときに `'a := ℕ` や `'a := ℝ` と具体化する。

これは ML の多相型（`'a list`）や、論理学で言う **図式**（schema：記号に何を入れても成り立つ文の型）と同じ。

ソート変数の上では数の演算は使えない（`'a` に `+` があるか分からない）。`x + 1` を含む定理は、
`x` の型を決めないと書けない。

## 2.6 関数記号を引数にとる定義

```narfi
def is_lim(a : ℕ → ℝ, α : ℝ) := ∀ε>0. ∃N:ℕ. ∀n≥N. |a(n) - α| < ε
```

`a` は値ではなく **関数記号**（数列）。v2.0 は一階なので、関数を値として扱えない
（`∀a:ℕ → ℝ. …` とは書けない）。そのかわり、定義や定理のパラメータとして関数記号を受け取り、
**別の関数記号の名前** に付け替えることだけを許す（`is_lim(b, β)` は `a` を `b` に付け替える）。

`(a + b) ⟶ α + β` のように「数列の和」を渡すには、`n ↦ a(n) + b(n)` という **関数そのもの** を
作る必要がある。これが λ 抽象で、v2.1 の課題（第6章）。

## 2.7 確かめてみる

```sh
cargo run -- check tests/unsound_sorts.narfi    # 型の誤りがすべて止まる
```

`src/kernel/tests.rs` の `rejects_wrong_sort_instantiation` は、elab の型推論を通さずに
「ℝ の項を ℕ の ∀ に渡す証明項」を kernel に直接渡し、kernel が止めることを確かめている。
