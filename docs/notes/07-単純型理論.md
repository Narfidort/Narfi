# 7. 単純型理論：関数と集合を値にする（v2.1）

## 7.1 一階述語論理で困ったこと

v2.0（多ソート一階述語論理）では、量化できるのは「数」だけだった。

- `∀a:ℕ → ℝ. …`（すべての数列について）が書けない
- `(n ↦ a(n) + b(n))`（数列の和）を作れない
- `or_elim` の `P` は「どんな命題でもよい」はずなのに、同じ名前の述語でしか使えなかった

数学では「すべての数列」「すべての集合」について語るのが普通で、これらは **関数や集合を値として扱う** ことを
要求する。これをかなえる一番素直な論理が **単純型理論**（Church 1940、HOL とも呼ぶ）。

## 7.2 型に → と Prop を足す

```
σ ::= ℕ | ℤ | ℚ | ℝ | Prop | σ₁ × … × σₙ → τ
```

- `ℕ → ℝ`：数列
- `Prop`：命題の型。`P : Prop` は「命題の変数」
- `ℕ → Prop`：自然数の **集合**（または述語）。`A : ℕ → Prop` で、`A(3)` は「3 ∈ A」
- `(ℕ → ℚ) → Prop`：有理数列の集合（コーシー列全体など）

集合を「述語」として扱うのが HOL の流儀。`{n : ℕ | n > 1}` は `n ↦ (n > 1)` という
「命題を返す関数」で、`2 ∈ {n : ℕ | n > 1}` は `2 > 1` と同じ（β 簡約）。

**なぜ「単純」か**：型が値に依存しない（`Vec n` のような型がない）から。依存型（Lean・Coq）より弱いが、
集合論の普通の数学はほぼ全部書ける（Isabelle/HOL・HOL Light で実証済み）。そして kernel が小さくて済む。

## 7.3 λ と β 簡約

`(n ↦ n + 1)` は「n を n + 1 に写す関数」。適用すると中身に代入する：

```
(n ↦ n + 1)(5)  →β  5 + 1
```

Narfi v2.1 では、λ を直接適用した形を **そもそも持たない**。関数型の変数 `f` に λ を代入した瞬間に
β 簡約してしまう（**遺伝的代入**、hereditary substitution、`src/syntax.rs` の `Term::subst`）。

```
f(5)  [f := (n ↦ n + 1)]  =  5 + 1      （f(5) の形は残らない）
```

こうすると kernel が比べる式はいつも β 正規形で、比べるのが簡単になる。
簡約が止まらなくなる心配（`(x ↦ x(x))(x ↦ x(x))` のような式）は、**型** が防いでいる。
単純型付き λ 計算では、型の合う式の簡約は必ず止まる（**強正規化定理**）。kernel は代入の前に型を
検査するので、この定理が使える。

## 7.4 変数の捕獲

λ を代入するときも、束縛変数の捕獲に注意が要る：

```
∀y:ℕ. f(y) = y     に   f := (x ↦ y)   を代入する（y は外の変数）
```

素朴に置き換えると `∀y. y = y` になってしまう（外の y が ∀y に捕まった）。正しくは束縛変数の名前を
変えて `∀y'. y = y'`。`src/kernel/tests.rs` の `lambda_substitution_avoids_capture` が、
kernel がこれを正しく扱うことを確かめている。

## 7.5 二階の図式の具体化とパターン単一化

`forall_and : (∀x. P(x) ∧ Q(x)) → ∀x. P(x)` を、`∀y. y > 0 ∧ y < 5` に使いたい。
`P`・`Q` に何を入れればよいかを elab が見つける必要がある：

```
?P(#1) ∧ ?Q(#1)   =?=   #1 > 0 ∧ #1 < 5       （#1 は束縛変数の仮の名前）
```

`?P(#1) =?= #1 > 0` は、穴 `?P` が **相異なる束縛変数に適用されている** 形をしている。
この形（**Miller のパターン**）なら解は一意で、`?P := {x | x > 0}`。一般の高階単一化は決定不能
（解があるか判定できない）だが、パターンの場合だけは一階と同じくらい易しい。λProlog・Isabelle・Lean も
この断片を使っている。実装は `src/elab/unify.rs` の `solve_pred`・`solve_app`。

もちろん elab が穴を間違って埋めても、kernel は代入した結果を検算するので、誤った定理は通らない。

## 7.6 外延性と選択

HOL では次の公理を置くのが標準（`src/prelude.narfi`）。

| 名前 | 内容 | なぜ要るか |
|---|---|---|
| `funext` | すべての点で値が等しい関数は等しい | 「関数 = 対応のしかた」という数学の約束 |
| `propext` | 互いに導ける命題は等しい | 命題の等しさを「同値」と同じにする |
| `setext` | 同じ元を持つ集合は等しい | 集合の外延性（ZF の外延性公理にあたる） |
| `choice` | 何かが P を満たすなら `some(P)` は P を満たす | 選択公理。定義できない関数を「選ぶ」 |

`choice` は Hilbert の ε 演算子と呼ばれるもので、選択公理（ZFC の C）と同じ強さ。
商（同値類）の上で関数を定義するときに使う（次の章）。

これらの公理は数学の標準的な基礎（ZFC）でも成り立つので、置いても矛盾は増えない
（HOL は ZFC の中にモデルを持つ）。
