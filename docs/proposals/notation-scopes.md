# 提案：記法は文脈ごとに宣言し、その範囲だけで効かせる（見送り）

> **見送り（2026-10-23）**：仕組みが大きく、標準の記法を 1 つに決める方針と、型で 1 つに決まるときだけの読み分け・宣言（[../language/notation.md](../language/notation.md)）で足りるため。考え方の記録として残す。

## 問題
v2.9・v2.10 の notation は、宣言したファイル全体に効き、import した先にも全部持ち込まれる。さらに「上付きは関数なら添字」を全員に効く組み込みにした。
数学では記法は人ごと・分野ごと・文脈ごとに違い（導関数だけでも `f'`・`ḟ`・`f^{(n)}`・`df/dx`・`f_x`・`D_x f`）、
「以下 … と書く」と宣言して、その範囲だけで使う。広く効かせると、ある人の習慣が別の人の邪魔になる（過剰適合）。

## 方針
**核は 1 つ。記法は、宣言した範囲だけで効く。誰でも同じに読むものだけを組み込みにする。**

## 1. 組み込み（いつも効く）
`|x|`、`x ≠ y`、`¬φ`、`2x`（数のあとの積）、範囲付き量化子 `∀ε>0`、λ `(x ↦ t)`、集合 `{x | φ}`、数列の添字 `a_n`（a が `ℕ → σ` のとき）。
これ以外（上付きの添字・導関数の記法・多重指数・極限の記号など）は、すべて記法の束に置く。

## 2. 記法の 2 種類（宣言の形は 1 つ）
```
notation 左辺 := 右辺
notation 左辺 := 右辺  for 名前 : 型, …
```

| 種類 | 左辺 | 読む時点 | 例 |
|---|---|---|---|
| 型紙 | 普通の式としては読めない文字の並び | 構文解析 | `a → α (n → ∞)`、`\lim_{n → ∞} a = α`、`x ⊕ y` |
| 型つき | 普通の式としても読める形（名前の飾り：添字・上付き・プライム・ドット） | 名前の解決（型が分かったあと） | `f'`、`ḟ`、`u^n`、`F_i^j` |

- 型つきの記法は `for` で入る所の型を書く。その型に当てはまるときだけ、その読み方になる（当てはまらなければ組み込みの読み方：`x^2` は冪）。
- 型紙は v2.9 の決まりのまま（右辺の引数が入る所、右辺の λ が束縛変数、普通の式として読める型紙は拒む）。
- 型つきの例：
  ```
  notation f' := deriv(f)               for f : ℝ → ℝ
  notation f^{(n)} := deriv_n(n, f)     for f : ℝ → ℝ, n : ℕ
  notation u^n := u(n)                  for u : ℕ → σ
  notation F_i^j := F(i, j)             for F : ℕ × ℕ → σ
  ```
  組み込みの `a_n` も、この形の記法（`notation a_n := a(n) for a : ℕ → σ`）を、いつも開いているものと説明できる。

## 3. 範囲
- `notation …` はどこにでも書け、書いた所から、それを含むブロックの終わりまで効く。
  - ファイルの最上位：ファイルの終わりまで
  - 定理の見出しのすぐ下・証明の中：その定理・そのブロックの終わりまで
- 範囲の中で、外の記法と同じ形の記法を宣言したら、内側が優先（変数の隠しと同じ）。
- あいまいさの検査は、その場所で効いている記法の間で行う。

## 4. 記法の束と open
```
notation set derivative.prime          -- ライブラリのファイルに置く
  notation f' := deriv(f)            for f : ℝ → ℝ
  notation f'' := deriv(deriv(f))    for f : ℝ → ℝ
  notation f^{(n)} := deriv_n(n, f)  for f : ℝ → ℝ, n : ℕ

open notation derivative.prime         -- 使う所で開く（ファイル・定理・ブロックのどこでも）
```
- import で入るのは定義・定理・束の名前だけ。記法は `open` したものだけが効く（原則 2：すべてを明示する）。
- 同じ概念に、人ごとの束がいくつあってよい（`derivative.prime`・`derivative.dot`・`derivative.leibniz`）。どれを開いても核の形は同じ。

## 5. 表示
Goal タブ・Prose・LaTeX は、その行で効いている記法で書く。同じ核の形に効いている記法がいくつかあれば、最も内側の範囲で、最初に宣言・open されたもの。どれも効いていなければ核の形（`deriv(f)(x)`）。
だから、同じ定理でも、書いた人が選んだ記法で表示される。

## 6. 宣言し忘れたとき
勝手に読まない（原則 2）。`f'` が名前としても記法としても読めなければエラーにし、
ライブラリの束から当てはまる記法を探して「`open notation derivative.prime` で読める」と直し方を出す（Tab で入る）。根拠の候補と同じ仕組み。

## 7. 今あるものの扱い（利用者がまだいないので、後方互換は付けない）
- 上付きを添字とする読み方：組み込みから外し、束 `index.super` にする。
- `notation a "⟶" α := …`（引用符の書き方）：読めなくする。
- ライブラリの略記（`a → α (n → ∞)`・`a ⟶ α`・`\lim`・`a ~ b`）：それぞれのファイルの束にし、使うファイルで open する。
- チュートリアル・テスト・仕様は一緒に直す。

## 8. 今回はしないこと
- `f_x`・`f_{xy}`（変数の名前で偏微分を表す）：関数の引数の名前を型に持たないので、今の核では表せない。多変数の微分のライブラリと一緒に考える。
- 型によって組み込みの演算子（`+`・`−`・`≤`）の意味を変える仕組み（多重指数の `α − β`・`β ≤ α`）：型つきの記法の延長で書けるかを、別に検討する。
- 読む人ごとに表示の記法を変えること（ロケールのレンズのような表示の層）。
