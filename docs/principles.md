# Narfi の設計原則

**Narfi** = **N**atural **A**nnotated **R**easoning **F**orward **I**nteractive（「ナーフィ」）。名前は作者のユーザー名 Narfidort から。

## コンセプト

手書きの証明と対応し、量化子を 1 つずつ剥がしていく自然演繹の前向きの推論を、そのまま書いて検査できる言語。
信頼できる検査器を持ちながら、数学の答案として読める。

## 原則

迷ったら、この 4 つに照らして決める。ぶつかるときは番号の小さいものを優先する。

1. **信頼は小さく** — 正しさを判断する部分（kernel）を小さく保ち、それ以外を信じなくてよい作りにする。
2. **すべてを明示する** — 証明に使ったものは、すべてソースに書かれている。推測したことは提案にとどめ、利用者が書くまで使わない。
3. **紙の証明に忠実に** — 数学の答案の順序・粒度・記法で書け、そのまま読める。書き方は 1 つ。
4. **壊さない** — 利用者の証明とデータを守る。失敗は局所的に、変更は移行の道とともに。

## 原則から出てくる決まり（v2.6）

| 決まり | 原則 |
|---|---|
| 新しい機能は今ある kernel の規則に落とす。kernel を変えるときは理由を仕様に書き、誤りを通さないテストを付ける。自動証明は証明書を出し kernel が検算する | 1 |
| 仮定の中身・事実の行の根拠は省略できない。分かったことはエラーの直し方（Tab）として示す | 2 |
| 表示を変えるもの（日本語の読み・∴ の表示・添字や積の見え方）はファイルを変えない | 2 |
| 名前を導入するのは `Fix`・`assume`・`Obtain`・`cases`・`induction`・`by_contra` の 6 つ（量化子を剥がす操作）。ほかは事実の行 `h : φ by j`・根拠・`choose`・`let`・連鎖 | 3 |
| 記法は教科書に合わせる（添字・数のあとの積・Σ）。読み方が 2 通りになるものは入れない。名前は `.` で階層を作る（対象.性質） | 3 |
| 同じことの書き方は 1 つ（例外：授業のための自然演繹の規則の名前） | 3 |
| 言語の核（予約語・記号・ファイルの書式）は ASCII で、自然言語に依存しない。日本語の読みは表示の層 | 3・4 |
| 1 つの宣言の失敗が、ほかの宣言の検査や表示を止めない | 4 |
| 書き方を壊す変更は、警告・自動の書き換え・版の更新とセットにする。保存されたデータは消さない | 4 |
