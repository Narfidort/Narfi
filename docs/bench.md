# ベンチマーク：各分野の証明

いろいろな分野の定理を、教科書の証明と Narfi の証明で並べ、記法・表示・ライブラリ・検査器の足りない所を見つけるための一式。
直すたびにここを更新し、少しずつ完成に近づける。

## 見方
- ファイルは `narfi/lib/bench/`。Web 版・ローカル版とも、左の **Standard Library → bench** から開ける（読み取り専用）。
- エディタ：``` で囲んだ所が「教科書の証明」と「Narfi での課題」（カーソルのない行は Markdown と数式で描かれる）。その下が Narfi の証明。
- **Prose タブ**：教科書の証明のすぐ下に、Narfi が証明から作った文章が出る。2 つを見比べて、記法と表示の良し悪しを判断する。
- テスト（`tests/examples.rs` の `benchmarks`）：構文エラーがないこと、✓ の定理が通り続けること。エディタで開いて保存しても結果が変わらないこと（`tests/ui.rs`）。

## 見つかった課題（優先度の高い順）
### 検査器（核）— 通るはずの証明が通らない
- **K1　集合を返す定義に要素を当てた形を開けない。** `cup(A, B)(x)`（$x \in A \cup B$）を $x \in A \lor x \in B$ まで開けない。kernel の δ（項の定義の展開）が、`∈`（適用）の中で β 簡約までしない。集合・測度の 5 つの ✗ のうち 4 つがこれ。**最優先。**
- **K2　等号で書き換えたあと β 簡約しない。** `EQ2` で `T(u)` を `(n ↦ 0)` に置き換えると `(n ↦ 0)(n)` が残り、`0` と同じと見なされない。

### 根拠の書き方 — 紙より手間がかかる
- **R1　代入。** 「$b = ak$ を代入する」が `by hk` では通らず、`EQ2(hk, refl)` と書く。
- **R2　∀ の仮定の具体化。** linarith は `∀n. a_n ≤ b_n` を使えず、`k : a_n ≤ b_n by hab(n)` と書き出す必要がある。
- **R3　関数どうしの等式。** `(k ↦ p_k(X_k + Y_k)) = (k ↦ p_kX_k + p_kY_k)` を `ring` で示せず、各点で ring してから `funext` で包む。Σ の中の変形が重い。
- **R4　帰納法の後者。** `Case succ k` の goal が $S(k)$ で書かれ、$k + 1$ に書き換える手間がかかる。
- **R5　命題を引数に渡せない。** `em(x ∈ A)` が構文エラー（`em` とだけ書いて単一化に任せる）。

### 記法（notation.md と合わせて）
- **N1** `∪`・`∩`・`∖` が組み込みの記号として読めるのに意味がない。標準の定義にする（K1 と一緒に）。
- **N2** `a ∣ b`（`∣` に意味がない）、`g ∘ f`、関数の点ごとの和 `f + g`、ベクトルの和・零。
- **N3** 文字どうしの積 `a k`（`a b` に決定、未実装）。
- **N4** 不等式の連なり `a_n ≤ b_n ≤ c_n`。
- **N5** $A^\complement$・$f^{-1}[B]$・$f[A]$・$\langle x, y\rangle$・$\|x\|$・$E[X]$・行列の積と $\det$・$\operatorname{tr}$（決定済み・ライブラリ待ち）。

### 構造・ライブラリ
- **S1** 型と演算をまとめた構造（ベクトル空間・内積空間・確率空間・ℂ）を表す仕組みがない。今は仮定に関数と性質を並べている。
- **S2** 帰納的に定義する述語（「道がある」）がない。
- **S3** 場合分けで定義する関数（`if … then … else`）がない。
- **L1** 実数の基本補題（$\min$、絶対値と区間、非負の数を掛ける）、冪 $x^n$ の性質、微分、二重和の入れ替え。今は各ファイルで公理として置いている。

### 表示
- **D1** Prose で、範囲付きの ∃ から取り出す文が「$\delta_1 > 0 \land (\dots)$ を満たす $\delta_1$ をとる」になる。紙では「$\delta_1 > 0$ で、… となるものをとる」。
- **D2** Prose の公理の表示が縦に長い（前提を 1 行ずつ並べる）。
- 直したもの（v2.12）：Prose の前提で仮定の名前が化ける（`hf` が `h_{cont_at}(f, a)` に）、`hδ₁` の LaTeX が不正（`h_{\delta}_{1}`）、エディタで ``` の中の行が数式として描かれる、Prose で注釈の見出し・箇条書きが描かれない。

## 進め方の案
1. K1・N1（集合の演算に意味を付け、kernel が開けるようにする）→ 集合・測度の 4 つが通るはず。
2. K2・R1・R3（書き換えと β、代入の短い根拠、関数の等式）→ 線形代数・確率が軽くなる。
3. L1（実数の基本補題を公理から定理へ）、D1・D2（Prose の読みやすさ）。
4. S1〜S3 は設計が要るので、別に相談する。
