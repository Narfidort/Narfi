# 5. 算術：探索と検算を分ける

## 5.1 何を仮定しているか

v2 は数のソートについて次を **仮定する**（仕様 §7）。これが算術の公理系。

- ℕ は可換な順序半環、ℤ は可換な順序環、ℚ・ℝ は順序体
- ℕ ⊂ ℤ ⊂ ℚ ⊂ ℝ は演算と順序を保つ埋め込み
- `S(n) = n + 1`、数字 `n` は `S(…S(0))` と同じ値

kernel の算術の規則（`Ring`・`LinArith`・`Decide`）は、この公理から **直接出ること** だけを
計算で確かめる。v1 との違いは、v1 では「計算して true が返ったから正しい」だったのが、
v2 では「この公理から出ることを、kernel の小さなコードで確かめた」になったこと。

## 5.2 ring：多項式の正規化

`l = r` を示すには、`l - r` を多項式として展開し、0 になるかを見る（`src/kernel/arith.rs` の `ring_eq`）。

```
(a + b)² - (a² + 2·a·b + b²)  →  a² + 2ab + b² - a² - 2ab - b²  →  0   ✓
```

多項式にならない部分（`abs(t)`・`max(s, t)`・`a(n)`・`x/y`）は **原子**（1つの変数）として扱う。

```
|a(n) - α| + |b(n) - β|   の原子は   |a(n) - α|  と  |b(n) - β|
```

原子の中身は正規化してから比べるので、`abs((a+b)-c)` と `abs(a-c+b)` は同じ原子になる。
これは **合同性**（等しい引数を入れれば、関数の値も等しい）を使っている。

`x/0` の値は決めていない（ℝ で 0 での割り算は定義されない）。`x/y` は原子なので、値を知らなくても
「`x/y + x/y = 2·(x/y)`」のような等式は正しく扱える。値を決めないことで、「`x/0` は何か」という
議論を避けている。

## 5.3 linarith：Farkas の補題

`x < 3` と `y ≤ x` から `y < 3` を示したい。目標の否定 `y ≥ 3` を加えて矛盾を出す。

```
(1)  3 - x > 0         （x < 3）
(2)  x - y ≥ 0         （y ≤ x）
(3)  y - 3 ≥ 0         （目標の否定 y ≥ 3）
```

(1)+(2)+(3) を足すと `0 > 0`。矛盾。この「足し方」（係数 1, 1, 1）が **証明書**。

一般には次の定理（**Farkas の補題**の一形態）が成り立つ：線形な不等式の集まりが矛盾するなら、
**非負の係数** で足し合わせて「0 > 0」や「負の数 ≥ 0」のような明らかな矛盾を作れる。
係数が非負でなければならないのは、不等式に負の数を掛けると向きが変わってしまうから。

kernel がすること（`farkas_check`）：

1. 各事実を `e ⋈ 0`（⋈ は > ≥ =）に直す
2. 不等式の係数が 0 以上かを見る（等式は符号自由）
3. 係数を掛けて足し、定数 k になるかを見る（5.2 の正規化を使う）
4. k < 0、または k = 0 で正の係数のついた `>` があれば矛盾

これだけ。**係数をどう見つけたか** には関心がない。

## 5.4 証明書を探す：Fourier–Motzkin の消去法

係数を見つけるのは elab の仕事（`src/arith.rs` の `find_certificate`）。変数を1つずつ消していく。

```
x を消す：x の係数が正の式と負の式を、x が消えるように正の数を掛けて足す
```

これを繰り返して、変数のない式が矛盾すれば成功。各式が「元の式を何倍して足したものか」（由来）を
持ち歩くので、矛盾した式の由来がそのまま証明書になる。

消去法は最悪で式の数が爆発する（指数的）。探索は重く、検算（掛けて足すだけ）は軽い。
**探すのは難しく、確かめるのは易しい** という非対称が、de Bruijn 基準がうまく働く理由。

## 5.5 型の混ざった事実は使えない

`n : ℕ` についての `n < 3` と、`x : ℝ` の目標 `x < 3` を一緒に足すことはできない（`n` と `x` は
別の世界の数）。kernel は事実と目標が同じソートかを確かめる。elab も、目標と同じソートの事実だけを
集めるようにしている。ℕ の目標のときは、ℕ の変数について `n ≥ 0`（`NatNonneg`）を事実に加える。

ℕ の事実を ℤ に埋め込んで計算するのは問題ない（5.1 の埋め込みが演算と順序を保つ）。

## 5.6 桁あふれ

有理数は 128 ビット整数の分数で計算する。Rust の release ビルドでは、整数の桁あふれは黙って
値が折り返す。折り返した値で「矛盾した」と誤判定すると、誤った定理を通すことになる。
kernel では桁あふれを検出したら **検査を止める**（`checked_mul` など）。止まるのは不便だが、
誤って通すよりはよい。

## 5.7 確かめてみる

```sh
cargo test --bin narfi arith::      # 証明書を探して kernel で検算する
cargo test --bin narfi linarith     # 間違った証明書を kernel が拒否する
```

`src/kernel/tests.rs` の `linarith_certificate` は、係数が足りない・負の係数で向きを逆にする・
型の違う事実を混ぜる、の3つを kernel が拒否することを確かめている。
