# 3. 自然演繹と証明項

## 3.1 判断と推論規則

自然演繹では **判断** `Γ ⊢ φ`（「仮定の列 Γ のもとで φ が証明できる」）を、**推論規則** で導く。
規則は「上の判断がそろえば、下の判断を導いてよい」という形をしている。

```
Γ, h:φ ⊢ ψ                Γ ⊢ φ → ψ    Γ ⊢ φ
──────────── →導入         ──────────────────── →除去
Γ ⊢ φ → ψ                       Γ ⊢ ψ
```

v2 の kernel は、この判断に「どの証明か」を表す **証明項** をつけて `Γ ⊢ p : φ` を扱う
（仕様 §4〜§5）。規則は証明項の形ごとに1つある（`src/kernel/check.rs` の `infer` の `match`）。

```
Γ, h:φ ⊢ p : ψ                       Γ ⊢ p : φ → ψ    Γ ⊢ q : φ
───────────────────────────── ImpI   ──────────────────────────── ImpE
Γ ⊢ ImpI(h, φ, p) : φ → ψ                Γ ⊢ ImpE(p, q) : ψ
```

コードでは、規則の下の命題を上の命題から **計算する** 関数になっている：
`infer(ImpE(p, q))` は `infer(p)` が `φ → ψ` の形で、`infer(q)` が `φ` と等しいときに `ψ` を返す。

## 3.2 Curry–Howard 対応との関係

証明項は、型理論の **Curry–Howard 対応**（命題 = 型、証明 = プログラム）を知っていれば見覚えがあるはず。
`ImpI` は関数を作ること（λ）、`ImpE` は関数を適用することにあたる。

ただし v2 は **型理論ではない**。命題と型（ソート）は別の世界にあり、証明項は「導出木の記録」で、
それ自体を計算したり、項の中に入れたりはしない。HOL Light（LCF 系）に近い立場で、
Lean・Coq（依存型理論）とは違う。どちらの立場でも de Bruijn 基準（第1章）は成り立つ。

## 3.3 固有変数条件：∀導入と ∃除去の注意点

自然演繹で一番間違えやすいのが、変数を一般化するときの条件。

```
Γ, x:σ ⊢ p : φ
────────────────────────── AllI    条件：x は Γ に現れない
Γ ⊢ AllI(x, σ, p) : ∀x:σ. φ
```

「x について何も仮定していないので、x は任意だった」から ∀ をつけてよい。もし Γ に `h : P(x)` が
あれば、x は「P を満たす特定の x」で任意ではない。kernel は、新しい変数の名前が文脈にないことを確かめる
（`src/kernel/env.rs` の `fresh_var`）。

∃除去も同じ考え方。`∃x. φ(x)` から「そういう x を1つとって w と呼ぶ」とき、w は何者か分からない
ので、**結論に w が残ってはならない**（`ExE` の「取り出した `w` が結論に残っている」というエラー）。

`src/kernel/tests.rs` の次のテストが、それぞれの条件を破った証明項を kernel に直接渡している。

- `rejects_generalizing_a_variable_in_a_hypothesis`：h : P(x) から ∀x. P(x)
- `rejects_escaping_witness`：∃x. P(x) から ∀y. P(y)
- `quantifier_swap`：∃x∀y から ∀y∃x は通り、逆は通らない

## 3.4 古典論理

`Raa`（背理法）は「¬φ を仮定して矛盾を出せば φ」。これは直観主義論理では使えない規則で、
v2 は古典論理を採用している（数学の普通の証明はこれを使う）。`dne`（二重否定の除去）は
`Raa` から導ける（`examples/basics.narfi`）。

## 3.5 表層の構文から証明項へ

Narfi の書き方（`Fix`・`Obtain`・`have`…）は、そのままでは推論規則ではない。elab（`src/elab/stmt.rs`）が
証明項に翻訳する（仕様 §10 の表）。翻訳の要点は **後ろに続く文を内側に包む** こと：

```narfi
Obtain N₁, hN₁ : conv_a(ε/2, pos_half(hε))
（残りの証明）
```

は

```
ExE( conv_a(…) の証明項,  N₁, hN₁.  （残りの証明の証明項） )
```

になる。「N₁ を取り出したあとの世界」が ExE の内側、という構造。だから elab は文を「先頭の1文」と
「残り」に分けて再帰的に読む（`seq` 関数）。v1 はループで1行ずつ読んでいたので、この点が一番大きく変わった。

### let は「定義的に等しい名前」

`let N := max(N₁, N₂)` は `Let(N, ℕ, max(N₁, N₂), …)` になる。kernel は内側で `N` と `max(N₁, N₂)` を
**同じもの** とみなす（ζ 簡約、第4章）。だから `hn : n ≥ N` を `ge.max.left` に渡せる。
`N.def : N = max(N₁, N₂)` も使えるように、`Cut(N.def, N = max(…), Refl(max(…)), …)` を入れている。
`Refl(t)` は `t = t` を示すが、ζ で `N = t` と同じなので通る。

### ∴ と依存の注釈

`∴ φ` と `Obtain N(ε)` の `(ε)` は、**証明項には何も残らない**。読み手のための確認で、elab が
「直前に示したものが φ か」「N が依存する変数が ε だけか」を確かめるだけ。論理的には不要なので、
kernel は見ない。これは「人のための検査」と「論理の検査」を分けた例。
